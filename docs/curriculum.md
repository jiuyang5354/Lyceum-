# 知识点先修关系与「下一步练什么」

## 问题

BKT 能回答「这个知识点掌握了吗」，但回答不了「现在该练哪一个」。之前 `/api/review/today` 只能给「到期的那几个」，学生要是把二次函数做错了，实际卡点可能在一元二次方程，甚至因式分解——补错了地方，练习再多也没用。

## 做法

- `lyceum/prereq.json`：73 条**直接**前置关系，覆盖数学、物理、化学、英语四科，允许跨学段（小学 → 初中）。
- `lyceum/curriculum.py`：加载即校验 + 三个纯函数。
  - 校验：每个名字必须真实存在于 `taxonomy.json` 同一学科；不许自环；DFS 检环，数据错了在导入时就报错。
  - `prereqs()` / `chain()`：直接前置 / 全部祖先（拓扑序，去重）。
  - `recommend(mastery, due)`：给出 `{subject, topic, reason, p_l, blocked_by}`。

## 推荐规则（确定性，可解释）

1. 从最弱的到期知识点出发。
2. 沿先修链往下找**有作答证据、但 P(L) < 0.85** 的那一步；最多走 3 层。
3. 遇到**没有作答记录**的前置就停下——继续往更早的课追，会推到两三个学期以前，对学生没有帮助。
4. 前置都稳 → 推荐到期项本身；没有到期项 → 推荐掌握度最低的一项。

输出里 `reason` 直接给用户看：

```
整式的乘法 还没稳（0.60 < 0.85），先补这一步再看 因式分解
一元二次方程 还没学到（0.00），先补这一步
到期复习，上次掌握度 0.55
```

## 接口变化

`GET /api/review/today` 增加一个字段 `next`（对象或 `null`），其余字段不变：

```json
{"next": {"subject": "数学", "topic": "整式的乘法", "p_l": 0.6,
          "blocked_by": "整式的乘法",
          "reason": "整式的乘法 还没稳（0.60 < 0.85），先补这一步再看 因式分解"}}
```

只读：不改掌握度、不写事件、不调模型。

## 测试

`tests/test_curriculum.py`（14 项）覆盖：数据引用完整性、成环/未知知识点在加载时报错、拓扑序、前置未稳时先补前置、没到期也补前置、无证据时不越追、打平时结果确定。

## 边界

- 先修关系是人工整理的，只覆盖 73 条边、4 个学科；语文、生物、历史、地理还没有。
- 只影响「推荐哪一题」和它的理由，不改变提示词、不改掌握度算法。
- 没有题库，所以推荐到知识点为止，具体出哪道题仍由变式题生成决定。
