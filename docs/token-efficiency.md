# Token-budgeted tutoring：架构与验证

基线：`c62e6bf399af929bde0c333ae2ffc81465f29a97`。运行时继续只用 Python 标准库；没有引入多 agent 框架、向量数据库或压缩模型。

## 决策依据

先检查了指定的 Makeroom 论文目录；没有将该目录当作本项目教学效果的证据。[1]

Anthropic 的 context engineering 文章建议选择最小、高信号的上下文集合，按需加载资料，并提醒压缩可能损失重要信息。官方页面直连失败，本轮通过文本镜像阅读，不能将检索摘要冒充全文。[8]

LLMLingua-2 将压缩建模为 token 分类，研究了抽取式压缩和跨任务泛化，同时讨论了训练数据主要来自 MeetingBank 的局限。这里借鉴预算分配与忠实保留的思路，**没有安装 LLMLingua-2，也没有把其压缩倍数当作 Lyceum 的收益**。[7]

对教学场景的选择：不改写题干、学生数字/公式和安全原则；不增加一个“总结模型”来省另一个模型的 token。优先从确定无关的知识点表、旧对话、重复校正调用中节省。

## 调用链

```text
答疑请求
  → agent._prepare：服务端授权、学科/模型角色路由
  → context.select_history + 按学科知识点表
  → llm：请求选项协商、模型回退、usage
  → 答案闸门 + 数学工具核验
  → 共享至多一次修正机会 → 状态更新

批改请求
  → 本地 deterministic_grade
  → 能判的直接生成反馈
  → 无法判的合并为一次模型调用
  → 校验结果数量、布尔类型 → 按原索引合并
```

Lyceum 原本不是任意 MCP/function-calling 工具循环。本次优化真实的 Python 工具与模型调用链，不为了名义上的“工具化”增加框架。

## 变更

### 1. 按需上下文

- `taxonomy.prompt_block(..., focused=True)`：已知学科只发送该学段、该学科的规范标签；未知学科保留完整表。服务端完整规范化索引不裁剪。
- `context.select_history`：仍至多查看最近 14 条历史，按完整 user/assistant 交互选择连续的最近历史，默认 6000 **字符**软预算。
- 最近两次完整交互始终保留，即使超过预算；当前输入、当前题干、安全规则不受此历史预算裁剪。不会将数学表达式截成半句。
- 省略历史时明确提醒模型：缺少早先条件或步骤就请学生补充，不能猜。不会伪造一段“压缩总结”。
- `LYCEUM_HISTORY_CHARS` 可设 1000–24000；非法值回到默认。它不是供应商 token 上限，也不是硬性的总请求上限。
- 每轮响应的 `context_usage` 返回发送/省略历史的字符统计；不记录额外学生原文。

### 2. 缓存友好的提示词布局

固定教学原则与 JSON 契约放在前缀，年级、题干、学科策略和记忆放后面。后续题干未变化时要求 `problem` 为空字符串，由现有状态保留原题。是否获得供应商缓存优惠取决于上游；本轮没有把潜在缓存命中算成 token 节省。

### 3. 本地工具优先

能用已有数学核验器判定的练习不再发给模型。混合批次只发送未知项，并按原索引合并。模型漏项、多项、非布尔 `correct` 均报错，不把“没批出来”写成错误证据。没有扩大现有数学核验器的能力声明；其原有表达式覆盖边界仍存在。

### 4. 有界修正

漏答案重写与数学误判校正共享一次修正调用机会，避免同轮连续三次模型生成。修正请求保留原系统策略/当前状态、最近两轮完整交互、本轮输入（含图片）、待修正文和纠正指令，不重发更早的旧对话。上一轮学生原过程必须保留，否则“刚才那一步哪里错了”会失去指代对象。仍不合格则用原有确定性反馈，不无限重试。

这个上限约束的是**逻辑生成/修正次数**，不把网络重试、备用模型和兼容性协商假称为零。既有网络重试与备用模型配置仍生效。

### 5. 授权修复

模型 `stage=full/redirect` 不再取得答案放行权。流式直通只认服务端 `allow_full`；未授权的 full 内容也不能把会话标成已展示完整答案。每条 SSE delta 都经过对应规则，不能靠最后替换“收回”已泄露答案。

规则护栏仍不是完整的语义安全证明；文科等原有未覆盖区域没有因此变成全面检测。

### 6. 上游选项与用量

- 流式请求主动要求 `stream_options.include_usage`。
- 只有 400 错误明确提到不支持相关字段时，才移除 `stream_options` / `response_format`；按 endpoint/model 在进程内记忆，减少后续重复协商。无关 400 不静默剥除格式。
- 流式 usage 按最终累计快照计一次，记录缓存 token，精确的 0 不再当成缺失。
- 缺失用量用既有估算规则，并增加 `estimated_calls`。每模型累计保留兼容字段；估算值不冒充供应商计量。
- 流式断开/主动关闭也记录已知用量或估算，增加 `interrupted_calls`；流式出字后不自动切备用模型。
- 协商缓存进程重启后清空；并发首次请求仍可能各协商一次。未新增响应内容缓存，不混用学生数据。

## 可复现的本地对照

以下是固定**合成输入**的 `o200k_base` 文本编码计数，不是实际 API 账单。不包括图片编码、协议包装、模型输出 token 或缓存折扣；没有运行真实模型教学质量评测。

| 场景 | 原输入文本 token | 新输入文本 token | 减少 | 逻辑模型调用 |
|---|---:|---:|---:|---|
| 数学首轮 | 2853 | 1999 | 29.9% | 1 → 1 |
| 数学续问 | 2879 | 2025 | 29.7% | 1 → 1 |
| 物理首轮 | 2862 | 1945 | 32.0% | 1 → 1 |
| 长历史 | 13537 | 6393 | 52.8% | 1 → 1 |
| 学科未知 | 2967 | 2973 | **增加 0.2%** | 1 → 1 |
| 图片输入的文字部分 | 2880 | 2026 | 29.7% | 1 → 1 |
| 全部可本地核验的批改 | 174 | 0 | 100% | 1 → 0 |
| 混合批改 | 202 | 133 | 34.2% | 1 → 1 |
| 漏题 + 误判双重修正（长历史） | 40755 | 8647 | 78.8% | 3 → 2 |

最后一行是特意触发双重修正的压力场景，不能推广成所有对话都省 79%。学科未知场景没有省 token，因为保留完整分类信息比强压缩重要。

## 尚未证明与不做的事

- 没有用真实学生数据或付费模型测试教学质量，因此不声称效果无损。
- 不通过极低 `max_tokens` 强行截断 JSON，不压缩学生数字/否定词/公式，不缓存学生答案。
- 长历史仍可能省略较早的重要条件；已有当前题干与最近作答兜底，并要求缺失时追问。需真实评测决定是否引入显式条件账本。
- 不改变主界面、持久化 schema、学生数据格式或现有安装依赖；不自动发布新安装包。
