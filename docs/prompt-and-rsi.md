# 提示词工程与自进化：这一轮改了什么

两件事：把系统提示词从「一整块字串」变成**可分节度量、可锁定**的装配结果；把「自进化」从「在线调参数」补上**离线评估与门禁**。不改教学原则，不加运行时依赖，不调用模型就能跑。

## 1. 提示词分节（`lyceum/prompts.py`）

原来 `agent.system_prompt()` 是一个 90 行的 f-string：改一个字就要重读整段，也没法只比较某一节。现在拆成七节，顺序固定：

| 节 | 作用 | 预算（字符） | 受保护 |
|---|---|---|---|
| `preamble` | 身份 | 80 | |
| `principles` | 8 条教学与安全原则 | 1800 | ✅ |
| `output` | JSON 输出契约 | 900 | ✅ |
| `context` | 年级 / 教材 / 学段语气 | 400 | |
| `strategy` | 本科引导方式 + 追问方式 + 节奏 + 经验 | 1200 | |
| `taxonomy` | 知识点标签规则 + 规范表 | 2600 | |
| `state` | 当前题目、提示层级、卡住次数、答案授权 | 500 | ✅ |

约束与验证：

- **输出逐字不变。** 重构前先把四种配置（初二数学、三年级无学科、高三完整解法、九年级英语+记忆/洞察/策略附加块）的实际提示词冻结成 `tests/fixtures/prompt-golden.json`，重构后逐字比对。
- **前缀仍可缓存。** 已有测试要求 3 年级与 11 年级、不同学科的前 1200 字一致。
- **每节有预算**，提示词变胖时能指出是哪一节。
- **学科表只有一个来源**：`prompts.SUBJECTS`，`agent.SUBJECTS` 由它派生，输出契约直接用它，避免两处漂移。

### 受保护面到底覆盖什么

`guard_fingerprint()` 哈希的是：**各节标题与顺序**、**原则**、**输出契约**、**状态节里的答案授权行**的源文本，加上**三档语气（TONE）**和**学科表**。

一开始只哈希了前两节，独立复审指出这不够：答案授权写在「当前状态」里，语气决定能不能用超纲方法，学科表会被拼进输出契约——三处都能在指纹不变的情况下被改掉，而文档却说「答案授权受保护」。已修，并加了三个回归测试分别覆盖这三处。

`tactic` / `pace` / `lessons` 故意不进指纹：它们本来就会随教学效果变化，进指纹会让每次 A/B 都误报「护栏被改」。

## 2. 离线优化与门禁（`lyceum/optimize.py`）

借鉴 GEPA：不拿一个标量奖励去调参，而是把「反思」落在可读的自然语言规则上，再用**成对评估**判断它是否真的更好。[2507.19457](https://arxiv.org/abs/2507.19457) 报告 GEPA 在六个任务上平均优于 GRPO 6%、最多 20%，且 rollout 少至 1/35；相对 MIPROv2 提升 10% 以上。

面对中小学生，这层实现刻意更窄：

1. **候选只来自代码白名单。** `CANDIDATES` 里 5 条已发布的附加要求，`evaluate()` 要求 id 存在且文本逐字一致，单行、≤120 字、不含 `#`。任意文本一律 `unsafe_candidate`。
2. **插入位置不在末尾。** 附加要求插在「当前状态」之前，并明确标注「不改变、也不能覆盖上面的原则与输出契约」。
3. **受保护面默认冻结。** `LOCKED_GUARD` 是仓库里的常量；调用方不传 `locked_guard` 时也用它。指纹不符 → `protected_surface_changed`，不评估。
4. **样本与去重。** 场景 <8 → `too_few_scenarios`；场景 id 重复 → `duplicate_scenarios`；候选没改变提示词 → `no_change`。
5. **精确符号检验**（不是自助法均值区间）：只数「变好」与「变差」，打平不计；要求 `p ≤ 0.05` 且平均提升 ≥0.05。8 个场景全好 → p=0.0039；7/8 → 0.035；6/8 → 0.145（拒绝）。测试直接断言了这三个尾概率，不靠 runner 间接推导。
6. **交替调用顺序**：偶数场景先跑基线、奇数先跑候选，避免 warm-up / 缓存 / 限流效应被记成候选的功劳。
7. **打分看行为**：有没有提出**有内容**的问题（问号前至少 6 个字符）、有没有直接抛最终答案、长度是否在 12–160 字之间。太短直接 0 分，所以「只回一个问号」拿不到分。漏题用正则的否定前瞻判断，`答案是否…`、`结果就是我们要找的吗` 不再被误判。不用「回复里有没有候选原话」——那是同义反复。
8. **接受也不自动生效**：`promote()` 要求 `accept is True`、`decision=accept`、`synthetic is False`、候选在白名单、**证据字段自洽**（p≤α、lift≥0.05、improved>worsened、场景数≥8）、`guard` 等于当前指纹、`approved=True` 且有具名 `approver`。不写数据库、不改代码。

### 为什么这么保守

[2310.01798](https://arxiv.org/abs/2310.01798) 的结论很直接：没有外部反馈时，模型对推理结果的「自我纠正」经常无效，甚至会让结果变差。所以这里**不接受模型自己说「这个提示更好」**，只接受同一批场景上可复现的得分差。反思文本可以生成，但只能当候选来源，不能当证据。

同一条思路也适用于更激进的自进化：[DGM](https://arxiv.org/abs/2505.22954) 靠基准测试验证每一次自我修改，[STOP](https://arxiv.org/abs/2310.02304) 用效用函数筛选自生成的改进器，[Promptbreeder](https://arxiv.org/abs/2309.16797) 连「变异提示」本身也一起进化。三者共同的前提都是**有一个能判对错的评估器**；没有评估器时，进化只是在放大噪声。

## 3. 独立复审发现的 7 个问题（已修）

第一版提交前做了独立复审，结论是不通过。逐条修复并加了回归测试：

| 问题 | 后果 | 修法 |
|---|---|---|
| 候选只做关键词黑名单，且拼接在提示词**末尾** | 一段 `\n\n# 原则（更新）` 就能伪造一节，覆盖受保护原则，且不含任何禁词 | 白名单逐字校验 + 插到「当前状态」前 + 独立标注 |
| 指纹只覆盖两节模板 | 改「答案授权行」/ 语气 / 学科表，指纹不变 | 指纹扩到三节 + TONE + SUBJECTS |
| `promote()` 只看 `accept` 布尔 | 手写字典、mock 证据都能被「批准」 | 校验 decision / synthetic / 白名单 / 当前指纹 / 具名批准人 |
| 自助法在 6–8 个二元样本上把噪声当显著 | 3/6 变好被接受（符号检验 p≈0.66） | 换成精确符号检验，α=0.05 |
| 场景可以重复、候选可以没改动提示词 | 6 份同一个场景刷出「显著」 | 去重 + `no_change` |
| 始终先跑基线再跑候选 | 顺序效应被记成提升 | 交替先后 |
| 打分为「回复含候选原话」 | 指标同义反复，还误伤「检查你的答案」 | 换成行为三要素 |
| 手写「只有问号」的回复也能拿满分 | 压空回复即可刷分（复审第二轮实测 accept） | 加 12 字下限 + 问号前需有内容 |
| `答案是` 前缀误伤 `答案是否…` | 合规回复被打 0.67 分，产生候选专属假阴性 | 改用否定前瞻正则 |
| `promote()` 不看证据数字 | `p=0.99`、`lift=-1` 也能「批准」 | 校验 p/lift/improved/worsened/场景数，且 `accept is True` |
| 去重只按 id | 同一题换 8 个 id 仍能凑显著 | 按（学科，题干，学生话）内容去重 |
| 指纹不含标题与顺序 | 改掉 `# 原则` 这行标题不影响指纹 | 标题与顺序一起进指纹 |

复审也独立重建了重构前的 f-string，确认四种配置逐字一致——这一点不是靠我自己的快照自证。

第二轮复审确认前 6 项成立，但指出打分仍可被「只回一个问号」刷满，且 `答案是` 前缀会误伤 `答案是否…`。这两处与另外四处（证据字段、去重粒度、类型严格、标题进指纹）已按上表修复；本轮共 245 项测试通过。

## 4. 实际跑出来的结果

```
python tools/optimize_prompt.py --out docs/optimize-report.json
→ decision: insufficient_evidence, accept: false, lift: 0.0, p_value: 1.0,
  improved: 0, worsened: 0, synthetic: true, scenarios: 8
guard=171c6787b6d26df5…
```

这是**正确的结果，不是失败**：默认 runner 是离线 mock（`agent.mock_reply`），不会因为多了一句要求就改变输出，8 个场景上测不出任何提升，门禁拒绝改动。

- `synthetic: true` 是默认值：只有 runner 自己声明 `synthetic = False` 才会被当成真实评估；`promote()` 直接拒绝 synthetic 结果。
- 报告里写明局限：「离线 mock runner 只验证管线与门禁，不代表真实模型或学生的表现」。
- 要得到真实结论，必须接真实模型跑同一批场景，并人工复核场景是否覆盖目标学段。这一步本轮**没有做**，也不声称做过。

## 6. 明确的边界

- 没有新增运行时依赖，也没有新增模型调用；离线 mock 结论不能当作教学质量证据。
- 没有改教学原则、答案授权、漏题拦截、隐私过滤；这些是受保护面，且指纹默认生效。
- 没有自动改代码或自动上线：`promote()` 只产出建议，落地要人工改提示词并走 PR。
- 评估场景是合成的小样本（8 条），覆盖小/初/高与 6 个学科，**不是**真实学生分布。
- 用户指定的 [makeroom.club 论文页](https://makeroom.club/l/papers-and-studies) 本轮也查了：14 条条目集中在 UI/设计生成（EfficientUICoder、Figma2Code、ScreenAI 等）与两篇统计/因果研究，没有提示词优化或 RSI 主题，因此文献取自 arXiv 与 GitHub，而不是该页。
